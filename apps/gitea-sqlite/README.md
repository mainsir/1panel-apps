## 产品介绍

本应用使用 SQLite 部署单容器 Gitea，提供 Git 仓库托管、代码审查、工单和项目协作功能，无需单独部署数据库。

## 功能

- 支持 HTTP 和 SSH 仓库访问。
- 使用内置 SQLite 数据库保存应用数据。
- 提供 Pull Request、Issues 和代码审查。
- 支持 Gitea Actions；执行任务需另行配置 Runner。

## 默认端口

| 用途 | 宿主机端口 | 容器端口 |
|---|---|---|
| Web | 3000 | 3000 |
| SSH | 222 | 22 |

首次安装时，在 Gitea 初始化页面填写实际访问地址。

修改安装参数中的 SSH 端口后，Gitea 展示的 SSH 克隆地址会使用新端口。使用反向代理或修改 Web 端口后，还需检查 Gitea 的公开访问地址 `ROOT_URL`。

## 数据目录

`./data` 映射到容器的 `/data`，包含配置文件、仓库和 SQLite 数据库。初始化脚本设置 UID/GID 为 1000。升级或卸载前应备份该目录。

## 运行环境

- 镜像：`gitea/gitea:28.2.0`
- 架构：amd64、arm64

## 安全与升级

- 安装后请立刻打开页面完成初始化。完成前，任何能访问该端口的人都能打开安装向导，建议先用防火墙限制来源。
- 新安装默认关闭自助注册，因此必须在向导中创建管理员账号。之后可在 `data/gitea/conf/app.ini` 中调整。
- 向导里的「HTTP 服务端口」请保持 `3000`：这是容器内端口，容器启动时会强制改回。对外端口只在 1Panel 参数中修改。
- 从 1.27.x 升级到 28.x 前请先备份。28.0 调整了出站规则：`ALLOWED_DOMAINS`、`BLOCKED_DOMAINS` 和 `ALLOW_LOCALNETWORKS` 已弃用，`ALLOWED_HOST_LIST` 在默认模式下不再限制公网地址。用过这些设置，或有镜像同步、仓库迁移的，升级后请复测。
